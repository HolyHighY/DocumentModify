# 02 外网操作规范

## 1. 开始条件

先读 [通用规范](01-common.md)，按 [报告类型](04-report-types.md) 和 [表单](05-templates.md) 建立任务。默认外网材料仅包含公开信息、合成样例和明确允许提供的内容；不知道实际数据时，准备结构和方法，不替内网生成结果。

外网任务可包括研究、分析方法设计、绘图脚本、模板准备和公开报告的完整写作。若报告含内网材料，默认采用单向交接：外网交付准备包，内网按所选交付模式完成实际分析与内容检查。`md-only` 由内网 AI 交付 Markdown 正文及必要图片资源，用户用已有内网应用手动转换为 Word 并完成排版验收；不把外网准备包等同于报告已定稿。

模板只在内网时，按 [START.md](../START.md) 先准备公开研究资料，不以取得模板为前提。外网工作目录采用 `.local/projects/<项目ID>/`，只将 `outgoing/` 下显式准备的资料包带入内网。

## 2. 公开资料研究与起草

1. 明确问题、检索范围、资料截止日期、纳入与排除条件。优先原始论文、标准、官方手册和权威数据。
2. 记录实际查阅的来源、支持位置和结论；对无法访问的资料标记待核实。
3. 有模板时依据模板建立大纲；无模板时按研究问题组织独立知识模块，标明用途、来源、适用条件和待补项。建议结构仅为暂定，模板约定留到内网解析后建立。起草背景、理论、通用方法和明确标注的示意内容。
4. 对未知设备、材料、参数和测试过程使用待填字段，不把典型配置写成实际配置。
5. 为内网提供数据输入约定和分析方法：字段、单位、有效范围、缺失值处理、计算公式、绘图要求和预期输出。

已有普通 DOCX 模板时，先做副本提取结构和样式；若工具无法保留复杂公式、域或页眉页脚，记录限制，保留模板原件供内网使用。不能用纯文本转写覆盖唯一模板。

## 3. 可离线执行的内容

- 图表优先保留可编辑源和生成脚本。脚本只处理声明的输入，不在运行时下载资料、字体或模型。
- 对脚本用合成数据验证正常输入、必要的异常输入和输出含义；示例带明显标记，与正式数据隔离。
- 记录 Python/工具版本、依赖及安装方法。依赖需要内网使用时，准备符合目标系统、CPU 和 Python 版本的离线安装包与上游完整性信息。
- 离线依赖不是默认必需；标准库能完成的工作优先用标准库。不能把某操作系统上的包直接当作另一平台可用的包。
- 字体、图片、文献和软件包均应确认携带及使用权限。不能为了包可运行而关闭签名、校验和或 TLS 验证。

## 4. 离线写作包

推荐包结构如下；没有需要的目录可以省略：

```text
writing-package/
  ENTRY.md                  # 内网从这里恢复任务
  task.md                   # 任务单与边界
  template-contract.md      # 已有可用模板时才提供；仅内网有模板时省略
  outline.md                # 可暂定，不能冒称来自内网模板
  glossary.md
  modules/                  # 无模板时的知识模块；建议 MODULE-001 等稳定 ID
  chapters/                 # 已有模板时的分章草稿、摘要及状态
  references/               # 来源清单、允许携带的资料与摘录
  assets/                   # 示意图、可编辑源
  analysis/                 # 输入约定、脚本、标注的合成样例
  guidance/                 # 本仓库规范及 document_check.py
  state/                    # 决策、待补事项、交接、验收记录
  MANIFEST.json             # 文件摘要
```

`ENTRY.md` 必须写明：报告目的、当前阶段、交付模式（已知时）、阅读顺序、模块索引、已完成工作、未验证假设、模板可用状态、内网下一步和禁止外传范围。内网先读取有效本机规程；未核验或条件改变时执行所选模式需要的验证。交接包应能脱离当前聊天独立使用。旧版本包随附的规范仅作为该版本记录，内网执行以当前仓库规范和任务单为准；不直接修改已冻结包。

各模块写清主题、可支持的论断、来源 ID 与支持位置、适用条件、草稿/图示位置、局限和待补项。内网按真实模板选择、拆分或合并模块，不把模块顺序当作最终章节顺序。

来源清单同时包含网络地址和离线定位。重要理论只有链接、没有可查阅证据时，明确列为内网待补，不宣称已提供完整离线依据。

## 5. 打包与交接验证

以下命令在已安装 Python 3 的终端执行，实际使用时替换路径。若仅有 `py -3`，用它替换 `python`。脚本路径也可指向包内随附副本。

```sh
python tools/document_check.py manifest --root /path/to/writing-package --output /path/to/writing-package/MANIFEST.json
python tools/document_check.py verify --root /path/to/writing-package --manifest /path/to/writing-package/MANIFEST.json
```

生成摘要后不再修改包。新增或修改文件时重新生成并验证。压缩包应先解压到一个新目录，再运行同一验证命令，以确认交接内容完整。摘要只证明文件一致，不证明资料正确或来源可信；核对交接来源和传递渠道。

使用合成材料演练 `ENTRY.md` 的恢复流程：找得到任务、模块或草稿、来源、模板状态和下一步，离线脚本不依赖外网。没有实际在断网目标机执行的步骤标记“外网验证，内网待验证”。

## 6. 外网交付门槛

- 任务、术语、状态与知识模块或大纲能够相互对应；模板不可见时明确留待内网适配。
- 事实来源和待补内容明确；示例与真实材料分离。
- 图片性质及输入数据约定清楚，提供必要的离线资料。
- 文件摘要验证通过，已知工具限制和内网验证任务写入交接说明。
- 不以索取内网原件或完整聊天为后续工作的前提。
